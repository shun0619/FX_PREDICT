# FX Predict — 自分専用 AI 分析・執行ターミナル

GMOコイン外国為替FXの公開API(口座・APIキー不要・無料)から価格を取得し、
LightGBMで次の足の方向を予測するローカルWebアプリ。

**半自動売買**に対応: 人がエントリーを決めてボタンを押し、
損切り・利確・トレーリングストップは機械が自動で処理する。
執行先はペーパー口座(練習用)→ OANDAデモ → 本番 の順に切り替えられる。

## 構成

```
backend/   FastAPI + LightGBM (ポート8000)
frontend/  Next.js 14 + TradingView Lightweight Charts (ポート3000)

backend/app/broker/   執行先の抽象化 (paper / oanda)
backend/app/trading.py    ロット計算・発注ガード・自動決済エンジン
backend/app/tradestore.py 実発注トレードの記録
```

- データ源: GMOコイン 外国為替FX Public API (`forex-api.coin.z.com`)
- クロスアセット: FRED (米10年金利 DGS10 / ドル指数 DTWEXBGS / S&P500) ※キー不要
- 経済指標: Forex Factory 週間カレンダー (1時間キャッシュ)
- 対応ペア: USD/JPY, EUR/USD, GBP/USD (流動性が高くスプレッドの狭い主要3ペア)
  - ペアを増やすとモデルの学習・検証・実績蓄積がそれぞれ必要になるため、
    実際に使うものだけに絞った方が検証が早く進む
  - 増やす場合は `gmo.py` の `SYMBOLS` と `lib/api.ts` の `SYMBOLS` の両方に追記
- 時間足: 15m / 1h / 4h
  (1分足・5分足は実測でエッジがほぼ無く値動きも荒いため対象外。
   実測値: 15分足の平均エッジ +0.5% / 1時間足 +3.1%。
   復活させるなら `gmo.py` の `INTERVAL_MAP` に戻し、
   `main.py` の DEFAULT_DAYS・TRAIN_DAYS、`trading.py` の _BAR_DAYS、
   `store.py` の _BAR_SEC、`features.py` の HTF_MAP、
   `config.py` の CHOICES、`lib/api.ts` の INTERVALS にも追記する)
- 過去データは `backend/data/cache/` に自動キャッシュ(確定日はディスク永続、当日分は8秒TTL)
- 予測履歴は SQLite (`backend/data/predictions.db`) に保存され、次足確定後に自動で正誤判定

## 起動方法 (Git Bash)

前提: Python 3.10+ / Node.js 18+

```bash
# ターミナル1: バックエンド
cd ~/Documents/Project/FX_Predict/backend
python -m venv .venv                  # 初回のみ
source .venv/Scripts/activate
pip install -r requirements.txt       # 初回のみ
uvicorn app.main:app --port 8000

# ターミナル2: フロントエンド (普段使いは本番モード推奨)
cd ~/Documents/Project/FX_Predict/frontend
npm install                           # 初回のみ
npm run build                         # 初回とコード変更後のみ
npm start
```

※ `npm run dev`(開発モード)はページを開くたびにコンパイルが走るため動作が重い。
コードをいじるとき以外は `npm run build` + `npm start` で使うこと。

ブラウザで http://localhost:3000 を開く。終了は各ターミナルで Ctrl+C。

## 最初にやること: モデル学習

「AI予測」ページの **モデル再学習** ボタンを押す(またはCLI):

```bash
cd backend && source .venv/Scripts/activate
python train.py --symbol USD_JPY --interval 15m
python train.py --all        # 主要ペア一括
```

学習時にウォークフォワード検証(時系列4分割)を行い、
**WF精度がベースライン(常に多数派を予測した場合)を上回っているか**が表示される。
上回っていなければそのモデルにエッジはないので参考程度に。
通貨ペア・時間足の組み合わせごとにモデルは別なので、切り替えたら再学習が必要。

## 自動売買 (ペーパー口座限定)

設定画面の「自動エントリー」をオンにすると、AIの判断だけで発注する完全自動売買になる。

- 条件: 確率が閾値以上(既定65%) **かつ** Entry Scoreが閾値以上(既定65点)
- 対象ペア・時間足・閾値は設定画面で変更可能。重要指標の警戒中は自動でスキップ
- 同じ足で二重に発注しない。既存のリスク管理(リスク%・同時保有数・日次損失上限・
  キルスイッチ)はすべてそのまま効く
- 決済(SL/TP・建値ストップ・トレーリング)は従来どおり自動

**実口座では動作しない。** `trading.py` の `AUTO_ENTRY_PAPER_ONLY = True` で
コード側からブロックしている。実弾に移すにはこの定数を変更する必要があり、
意識的な操作を強制する安全装置になっている。十分な検証データが貯まるまでは外さないこと。

## 自動化機能 (バックエンド起動中のみ動作)

- **常時予測** (既定オン): 学習済み全モデルで約1分ごとに予測→履歴記録。
  ブラウザを閉じていても実測正解率の検証データが貯まる
- **自動再学習** (既定オフ): 設定画面でオンにすると3/7/14日間隔で全モデルを再学習
- **自動採点**: 次足確定後に予測の正誤を自動判定(最大500本まで遡って未採点分を補完)

## 半自動売買 (手動エントリー → 自動決済)

役割分担は固定:

| | 担当 |
|---|---|
| 入るか / どちらに入るか | **人** (取引ページのボタン) |
| ロット計算 | 機械 (リスク%と損切り幅から逆算) |
| 損切り・利確の設置 | 機械 (発注と同時) |
| 建値ストップ・トレーリング | 機械 |
| 決済の執行 | 機械 (人が「今すぐ決済」もできる) |

### 移行手順 (この順に進める)

**1. ペーパー口座** — 設定 → 売買執行 → 接続先「ペーパー口座」+ 発注機能オン。
外部接続なし、初期残高100万円の仮想口座。GMOの実レート(bid/ask)で約定するので
スプレッド負けは再現される。まずここで発注→トレール→決済の流れに慣れる。

**2. OANDAデモ (fxTrade Practice)** — 実際のブローカーAPIに繋ぐ段階。
[OANDA Japan](https://www.oanda.jp/) でデモ口座を開き、fxTrade にログインして
「APIアクセス管理」から個人トークンを発行する。バックエンド起動前に環境変数を設定:

```bash
# Git Bash。uvicorn を起動するターミナルで設定する
export OANDA_TOKEN=xxxxxxxxxxxxxxxx-xxxxxxxxxxxxxxxx
export OANDA_ACCOUNT_ID=101-009-1234567-001
export OANDA_ENV=practice          # 既定値。デモ環境
uvicorn app.main:app --port 8000
```

設定画面で接続先を「OANDA」にすると口座残高が表示される。表示されればOK。

**3. 本番** — デモで十分な実績が貯まってから。トークンと口座IDを本番のものに差し替え、
`OANDA_ENV=live` と **`FX_ALLOW_LIVE=1`** の両方を設定する。
`FX_ALLOW_LIVE` が無いとバックエンド側で発注を拒否する(誤操作の保険)。
本番接続中は取引ページに赤い警告が出て、発注のたびにチェックボックスの確認が要る。

### 自動決済の仕様

初期値(すべて設定画面で変更可能):

1. 発注と同時に **SL = 建値 ∓ 1.5×ATR**、**TP** = entry.pyの算出値(直近スイングまたはATR基準)を設置
2. 含み益が **1×ATR** に達したら SL を **建値 ±1pip** へ移動(建値ストップ)
3. 以降 SL は **建玉後の最高値(売りは最安値)から 1.5×ATR** の距離を保って追従
4. SL は有利な方向にしか動かない。押し戻されても切り下がらない
5. SL または TP 到達で決済

トレール方式は ATR追従 / 固定pips / 直近安値高値 / 使わない から選べる。
オプションで「AI予測が2本連続で逆方向になったら決済」「重要指標の直前に決済」も有効化できる。

### リスク管理と安全装置

- **ロット自動計算**: 1トレードの損失が有効証拠金の指定%(既定1%)に収まる数量を逆算。
  1,000通貨単位に切り捨て、上限数量でクリップ
- **同時保有数の上限**(既定3)、**同一ペアの重複建玉の禁止**
- **当日の損失上限**(既定3%): 当日の通算損益が有効証拠金の-3%に達したら新規発注を停止。
  日替わりは NY 17:00 (UTC 22:00)
- **キルスイッチ**: オンの間は新規発注を全面停止
- **全決済ボタン**: 取引ページから全建玉を成行決済
- **発注機能そのものが既定オフ**。オンにするまで発注APIは動かない
- 発注機能をオフにしても、**既にある建玉の自動決済は動き続ける**
  (損切りだけ外れる状態が一番危ないため)
- SLの向きが逆(買いでSLが現在値より上など)の注文はサーバー側で拒否

### ペーパーとOANDAの決定的な違い

| | ペーパー口座 | OANDA (デモ/本番) |
|---|---|---|
| SL/TPの置き場所 | このアプリのメモリとDB | **OANDAのサーバー** |
| アプリ/PCが落ちたら | **損切りも止まる** | 損切りは生き残る |
| スリッページ・約定拒否 | 再現しない | 実際に起きる |
| 週末ギャップ・スワップ | 再現しない | 実際に起きる |

ペーパーはあくまで操作の練習用。**成績の評価は必ずOANDAデモで行うこと。**

## 特徴量 (39列)

- 自時間足の基本 (18): リターン、EMA乖離/クロス、RSI、MACD、ボリンジャー、ATR、
  ローソク形状、時間帯・曜日
- 一目均衡表 (4): 雲との位置関係、雲の厚さ、転換線と基準線の差、基準線からの乖離
- ダイバージェンス (2): RSI・MACDと価格の食い違い (+1=強気 / -1=弱気)
- サポート・レジスタンス (3): 直近の確定スイング高値・安値までの距離、レンジ内の位置
- 上位足 (6): 上位2時間足のトレンド・RSI・乖離 (確定足のみ、shift(1)で先読み防止)
- クロスアセット (6): 米10年金利・ドル指数・S&P500の前日/5日変化 (前日確定値のみ使用)

すべてATRで正規化し、スイング判定は確定に必要な本数だけ shift して先読みを防いでいる
(未来を隠しても過去の特徴量が変わらないことをテストで検証済み)。

## Entry Score (エントリー判定)

配点: AI信頼度40 + ボリンジャー位置20 + RSI位置20 + 過去の類似予測の的中実績20。
65点以上=良い / 45〜64=普通 / 44以下=悪い。
SL = ATR×1.5、TP = 直近96本のスイング高値安値(0.5〜3ATR圏内のとき)またはATR×信頼度係数。
スコアの妥当性は「AI予測」ページの答え合わせカードで検証できる(各帯30件以上で判断)。

## 仕組みと注意点

- **確定足ルール**: 予測・採点・学習・バックテストはすべて確定した足のみ使用
  (形成中の足を使うと学習時と条件がズレ、採点も1本ズレるため)
- **ラベル設計**: 次足リターンが `0.05 × ATR` 未満の微小変動は学習から除外(ノイズ対策)
- **イン・サンプル汚染の排除**(重要): 学習に使った期間を学習済みモデルで予測すると
  答えを知っている問題を解くことになり、成績が実力より大幅に高く出る(実測で53%→82%)。
  そのため次の2つを分離している:
  - バックテスト: 学習時に保存したウォークフォワード予測(未学習データに対する予測)のみ使用
  - 実測正解率: その足の時点で実際に出した予測のみ集計。停止中を埋めた分(is_live=0)は除外
- **バックテスト**: エントリーごとにスプレッド(既定0.2pips)を控除。
  未学習区間での成績なので実運用に近いが、スリッページ・スワップは未考慮
- **予測根拠**: LightGBMの pred_contrib(SHAP近似)による特徴量寄与
- **オフライン開発**: 環境変数 `FX_SYNTHETIC=1` で合成データ動作
- 為替の短期方向予測は本質的に50%近辺との戦い。本ツールは裁量判断の補助であり、
  予測に従った売買の結果を保証しない
- **執行についての注意**: 自動決済エンジンはバックエンドが動いている間だけ働く。
  OANDAに繋いでいればSL/TPはブローカー側に残るが、トレーリングによるSLの切り上げは
  バックエンドが止まるとそこで凍結する(その時点のSLは有効なまま)

## データ管理

- `backend/data/cache/` : 削除可(次回起動時に再取得されるだけ)
- `backend/data/predictions.db` : 予測履歴。削除すると実測正解率・答え合わせがリセット
- `backend/data/settings.json` : 常時予測・自動再学習・売買執行の設定
- `predictions.db` 内の `trades` テーブル : 実発注トレードの記録(削除すると取引履歴が消える)
- `predictions.db` 内の `paper_trades` / `paper_account` : ペーパー口座。取引ページからリセット可
- `backend/models/` : 学習済みモデル(再学習で上書き)

## モデルの差し替え

`backend/app/model.py` の `train` / `predict` / `predict_series` を置き換えれば
LSTM等に変更可能(API・フロントは無変更で動く)。特徴量は `app/features.py`。
